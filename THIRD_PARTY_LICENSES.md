# Third-Party Licenses

OmniFiles is distributed as a Chrome extension whose `src/` directory is
loaded and shipped as-is. In addition to OmniFiles' own MIT-licensed code
(see [`LICENSE`](LICENSE)), the distributed package **bundles third-party
software**, primarily inside the compiled `src/rclone.wasm` binary and the
`src/wasm_exec.js` runtime glue. This file documents those components and
reproduces their license terms, as required for redistribution.

> **Scope note.** `rclone.wasm` is a statically linked Go binary. The exact
> set of modules linked into it depends on the rclone backends compiled in
> (see `src/wasm-bridge/main.go`): **Google Drive, Microsoft OneDrive,
> Amazon S3, Dropbox, Google Cloud Storage, Google Photos, Crypt, and
> Memory**, plus rclone core and the `fetch()` transport patch. The lists
> below cover the principal modules for those backends and the license
> families that apply. The authoritative, per-module manifest — generated
> from the real `GOOS=js GOARCH=wasm` build and shipped inside the extension —
> is [`src/third-party-licenses.txt`](src/third-party-licenses.txt);
> see [Regenerating this file](#regenerating-this-file).

into [`src/third-party-licenses.txt`](src/third-party-licenses.txt), which

## Regenerating this file

The per-module manifest is generated from the real WASM build, not maintained
by hand. `build-wasm.sh` does this automatically as step 8, so a normal build
keeps `src/third-party-licenses.txt` current:

```bash
./build-wasm.sh
```

To regenerate it on its own against an existing build tree:

```bash
./tools/gen-license-manifest.sh build_tmp/rclone/fs/rc/js src/third-party-licenses.txt
```

The generator enumerates dependencies with `go list -deps` against the actual
`GOOS=js GOARCH=wasm` target, so it reflects what is genuinely linked into the
binary rather than everything `go.mod` permits, and it classifies each module
by matching its license file. It needs only the Go toolchain that the build
already requires.

> **Why not `go-licenses`.** The obvious tool for this cannot analyse this
> target: the js/wasm dependency graph contains ~220 standard-library packages,
> which report no module info, and `go-licenses` treats each one as a fatal
> error and exits without output (google/go-licenses#128). Both `v1.6.0` and
> `@latest` — currently the same release — fail identically. An earlier version
> of this document recommended it, and `build-wasm.sh` invoked it "best-effort",
> which meant the manifest was silently skipped on every build and never
> actually existed.

Commit the resulting `src/third-party-licenses.txt` alongside this document so
the shipped package contains the exact inventory of the modules actually
linked. Re-run it whenever `RCLONE_COMMIT` in `build-wasm.sh` is bumped.
